The Software Factory

Agents take a task from the Board, write its spec and plan, build it with tests, check it, review it and open a pull request in the right Blocks repo. You decide at two points: when the spec is written and when the PR is open.

System map

Everything runs on your Mac except Board data, which lives in Blocks, and the PRs, which go to GitHub. All three ways of running the factory go through one factory core, and only the core writes to the Board or GitHub.

Agents work only inside their task worktree. Hooks block pushes and secret files.

One task, end to end

A task starts with you and ends with you. In between, the core claims it and the stage agents work on it one at a time. Failed tests and reviewer change requests send it back to the implementer, and after the third failed try it stops at Blocked with a question for you.

The core pushes and opens the PR. With the PR gate off and a non-protected base, the core merges instead.

Inside one stage run

This is the Build stage under the SDK runner. The runner asks the core for work, starts the agent with only the worktree and tools it needs, then hands the result back to the core, which records it.

The other two modes call the same core commands, so the rules and the history are the same.

In every mode the factory CLI refuses a skipped stage, a closed gate or a direct change to dev, stg or main. A confused session can get stuck, but it can't break a rule.

Board data and who can write it

Six tables in the factory's own Blocks project. Blocks access rules enforce the important limits, so a bug in the core can't get past them.

An approval names the spec version you read. If the spec changes afterwards, the approval no longer counts and the task waits for you again.

Layers of safety

L1

Agents hold no keys

No Blocks credential and no PAT. Only the core has them, so only the core can push, open PRs or change the Board.

L2

Hooks

Block git push, Keychain and secret-file reads, and edits outside the task worktree.

L3

Branch guard

Written into the core and repeated in a git pre-push hook: nothing reaches dev, stg or main except through a PR.

L4

Blocks access rules

Approvals and settings are yours alone. History can only be added to.

L5

Limits and stop

Turn and cost caps per stage and task, at most 2 tasks at once, and a pause switch on the Board.

L6

Separate clones

The factory clones each repo for itself, so your own checkouts and uncommitted work are never touched.

Where things live

Everything is in ~/scratchpad/selise/the-software-factory. Nothing is added to the Blocks repos; agents only create branches and PRs there.

the-software-factory/
  board-ui/        Board page (React + Vite, Blocks hosted login)
  core/            stages, gates, history, git and PR rules + the factory CLI
  runner/          SDK runner (factory run)
  plugin/          loaded only for factory sessions
    agents/          spec-writer, planner, implementer, verifier, reviewer
    skills/          one per stage, plus /factory
    hooks/           branch guard, secret guard, run log
  repos/           os, iam, monitor, logic, data, localization, release
  .clones/         the factory's own clones + task worktrees
  docs/            specs, plans and this overview

Every repo has the same shape: a .NET server with xUnit tests, a Vite client with type-check, lint and vitest, and Playwright e2e. Phase 1 Verify runs the server build and tests and the client checks. E2E against the PR preview environment comes in phase 2.

Build order

  1. Blocks project and Board tables

    You create the project and run the deploys. A short spike first checks how much text a Blocks Data field holds.

  2. factory core and CLI

    Stage order, gates, history, claims, worktrees, push and PR rules, with tests.

  3. Board page

    Board, task, history and settings views on localhost.

  4. Plugin: stage agents, skills and hooks

    Includes the /factory command, so modes 2 and 3 work from here on.

  5. SDK runner

    factory run, two tasks in parallel, crash recovery.

  6. First repo, then the other six

    Start with Blocks Data, then OS, IAM, Monitor, Logic, Localization and Release.
